# BME688 향 분류 — 수집부터 실시간 추론까지 가이드

> 혼자서 처음부터 끝까지 할 수 있게 정리한 문서.
> 모든 숫자는 실측으로 확인된 값이다.

---

## 0. 오늘 할 일 한눈에

```
① 준비 점검      10분   병에 오일 새로 채우기, 에어컨 바람 확인
② 예열           10분   보드온도 43도 안정될 때까지
③ 수집           40분   Air/향 교대 블록 × 3묶음
④ 학습            5분   명령 4줄
⑤ 실시간 추론     -     predict_serial.py
```

**핵심 원칙 하나**: 수집 때와 추론 때의 조건이 **한 가지도 달라지면 안 된다.**
통 뚜껑, 병 규격, 보드 온도, 에어컨 바람, 센서 위치 — 향만 바뀌어야 한다.

---

## 1. 준비 점검

### 1-1. 병 (제일 중요)

| 항목 | 확인 |
|---|---|
| 오일 | **새로 채울 것.** 며칠 열어두면 가벼운 성분이 먼저 날아가 향끼리 비슷해진다 |
| 양 | 각 10ml 정도, 세 병 동일하게 |
| 규격 | **네 병 모두 같은 유리병.** 입구 넓이가 다르면 증발 속도가 달라져 향 차이로 오인된다 |
| 빈 병 | Air 블록용으로 **한 개 더** 필요 (유리 자체 기여분을 기준선에 포함시키기 위함) |

### 1-2. 환경

- **에어컨/선풍기 바람이 직접 닿지 않는 곳**
  (바람이 있으면 향이 통에 쌓이지 못해 신호가 3~10배 약해진다 — 실측)
- 김치통 뚜껑이 확실히 닫히는지
- 통 안에 이전 향이 남지 않도록 **10분 이상 환기** 후 시작

### 1-3. 펌웨어

| 목적 | 스케치 |
|---|---|
| 데이터 수집 | `bme688_dev_kit_logger.ino` |
| 실시간 추론 | `bme688_serial_stream.ino` |

⚠️ 두 스케치의 **히터 프로파일은 절대 수정 금지**.
`{320,100,100,100,200,200,200,320,320,320}` / `{5,2,10,30,5,5,5,5,5,5}`
이걸 바꾸면 지문 모양이 달라져 학습된 모델이 통째로 무효가 된다.

## 2. 수집

### 2-1. 예열 — 시간이 아니라 온도로 판단

전원 ON 후 시리얼 요약의 **보드온도가 42~43도에서 더 안 오를 때까지** 기다린다.
보통 5~10분. 냉간 시작이면 더 걸린다.

> 근거: 예열 1분차에 지문 모양이 0.066 변한다. 그런데 Woody 신호 크기가 0.168이다.
> 예열이 덜 되면 그 드리프트가 향 신호와 맞먹어 판정을 망친다.

### 2-2. 블록 조작

스케치는 **수동 모드가 기본**이다. 자동(3분)으로 바꾸려면:

| 조작 | 동작 |
|---|---|
| SW_NEXT 짧게 | 블록 종료 → 저장 + 정지 |
| **SW_NEXT 2초 길게** | 수동 ↔ 자동 전환 (LED 4번 반짝 = 자동) |
| SW_START | 시작 / 일시정지 |

**블록 하나**
```
① 뚜껑 열고 병 교체
② 뚜껑 열어둔 채 환기 2분
③ 뚜껑 닫고 1분 대기      ← 통 안 농도 평형. 빠뜨리면 블록 안에서 신호가 계속 변한다
④ SW_START → 15초 물러남 → 3분 자동 녹화
⑤ LED 길게 3번 = 완료, 자동 정지 → ①로
```

### 2-3. 순서 — 반드시 교대

```
Air  향  Air  향  Air  향  Air  향  ...
```

**향끼리 연달아 찍으면 안 된다.** 각 향 바로 옆에 Air가 있어야 그 시점의
센서 상태를 기준선으로 뺄 수 있다. 이걸 어겨서 정확도가 24%까지 떨어진 적이 있다.

**13블록 = 3묶음** (첫 파일 번호를 N이라 하면)

| 파일 | 향 | | 파일 | 향 |
|---|---|---|---|---|
| N-1 | *예열분, 버림* | | N+6 | **Air** |
| **N** | **Air** | | N+7 | Citrus |
| N+1 | Citrus | | N+8 | **Air** |
| N+2 | **Air** | | N+9 | Floral |
| N+3 | Floral | | N+10 | **Air** |
| N+4 | **Air** | | N+11 | Woody |
| N+5 | Woody | | **N+12** | **Air** |

전원 켜고 첫 파일 번호를 시리얼에서 확인한 뒤 표를 맞춘다.

### 2-4. 라벨 실수 방지

SD를 PC에 꽂자마자 **파일명에 향을 붙인다.**
```
LOG_0031.csv → LOG_0031_Air.csv
LOG_0032.csv → LOG_0032_Citrus.csv
```
(예전에 Woody/Citrus가 뒤바뀌어 결과를 잘못 읽은 적이 있다)

## 3. 학습

### 3-1. 폴더 정리

> `N` 은 수집 세대 번호(새로 시작할 때마다 1씩 올린다). 예: `data8`, `features8`.
> 단일 프로파일 수집이면 `parse_devkit_csv.py`, 멀티프로파일이면 `parse_devkit_multi.py` 를 쓴다.

```
scent\
├─ dataN\
│   ├─ Air\      (Air 블록 전부)
│   ├─ Citrus\
│   ├─ Floral\
│   └─ Woody\
└─ (스크립트들)
```

### 3-2. 명령

```powershell
cd C:\ArduinoProject\bme688_dev_kit_logger\scent

python parse_devkit_csv.py dataN\Air    AirN.csv    --label Air    --ignore-heat-stab
python parse_devkit_csv.py dataN\Citrus CitrusN.csv --label Citrus --ignore-heat-stab
python parse_devkit_csv.py dataN\Floral FloralN.csv --label Floral --ignore-heat-stab
python parse_devkit_csv.py dataN\Woody  WoodyN.csv  --label Woody  --ignore-heat-stab

python -c "import pandas as pd; pd.concat([pd.read_csv(f) for f in ['AirN.csv','CitrusN.csv','FloralN.csv','WoodyN.csv']]).to_csv('featuresN.csv',index=False)"

python baseline_correct.py featuresN.csv featuresN_bc.csv
python train_scent.py featuresN_bc.csv --no-temp-hum
```

### 3-3. 중간 점검

| 단계 | 확인할 것 | 정상 범위 |
|---|---|---|
| 파싱 | 채택률 | **90% 이상** |
| 파싱 | 더미 행 제거 | 약 87% (정상) |
| 기준선 | 짝짓기 목록 | 각 향에 인접 Air가 붙었는지 |
| 학습 | fold 경고 | **없어야 함** (있으면 세션 부족) |
| 학습 | 정확도 | **0.85 이상** |

### 3-4. 어떤 모델을 쓸 것인가

`train_scent.py`는 최고 조합을 골라 `scent_model.pkl`로 저장한다.
**하지만 실시간에는 `cycle_unit` 모델을 권장한다.**

`model_comparison.csv`에서 `normalize=cycle_unit` 행 중 가장 높은 것을 확인하고,
그 조합으로 만든 모델을 쓰면 **농도가 몇 배 변해도 흔들리지 않는다.**

> 근거: 신호를 2.5배 키웠을 때 `cycle` 모델은 정확도 0.745로 떨어졌고
> `cycle_unit`은 1.000을 유지했다. 이상 조건에서의 성능 차이는 0.01뿐이다.

### 3-5. 학습 데이터로 먼저 검증

```powershell
python predict_log.py Air=LOG_00N.csv Citrus=LOG_00N+1.csv Air=LOG_00N+2.csv Floral=LOG_00N+3.csv
```

`Air=` 로 표시한 파일은 기준선 겸 테스트 대상이 되고,
각 향에는 번호가 가장 가까운 Air가 자동으로 붙는다. **7/7 나오면 정상.**

## 4. 실시간 추론

### 4-1. 실행

아두이노 IDE를 **완전히 종료**한 뒤 (포트 충돌):

```powershell
python predict_serial.py --port COM5 --model scent_model_unit.pkl --reset
```

`--reset`은 예전 기준선을 버린다. 조건이 바뀌었으면 항상 붙인다.

### 4-2. 화면 읽는 법

```
02:14 | Citrus  확정(즉시) | S0.31* | 42.3C 24% |   Air ██  Citrus ██████████  ...  [▓▓▓▓▓░░░░░]
        ^라벨    ^확정방식    ^신호   ^온습도        ^클래스별 확률              ^사이클 진행률
```

| 표시 | 의미 |
|---|---|
| `확정(즉시)` | 확신도 0.85 넘어 한 사이클(11초)만에 확정 |
| `확정(투표)` | 애매해서 2회 일치로 확정 (약 23초) |
| `수렴중` | 아직 판단 중 |
| `S0.31` | **신호 크기** — 이 숫자가 모든 진단의 출발점 |
| `*` | 기준선 갱신이 허용되는 구간 (신호가 작을 때만) |
| `[신호약함]` | 향이 센서에 도달하지 못함 |

### 4-3. 기준선 확립

```
기준선 안정 대기  변동 0.087 (목표 0.030)  (센서 2/8)  — ★ 발향 금지 ★
```

**변동 숫자가 0.030 아래로 떨어질 때까지 기다린다.** 개수만 채우고 넘어가지 않는다.
안 떨어지면 환기가 덜 됐거나 예열이 부족한 것이니 그냥 더 기다리면 된다.

⚠️ 이 동안 **절대 향을 넣지 말 것.** 기준선이 오염되면 이후 전부 틀린다.

### 4-4. 속도 조절

```powershell
--vote 1        # 투표 끄기 (가장 빠름, 노이즈 있음)
--conf 1.1      # 즉시확정 끄기 (가장 신중)
--alpha 0.25    # 기준선 더 빠르게 추종
```

## 5. 문제 진단

### 5-1. 기준 숫자

| 항목 | 정상 | 확인 방법 |
|---|---|---|
| 신호 크기 | **0.15 ~ 0.5** | 화면의 `S` 값 |
| 기준선 변동 | **0.030 미만** | 부트스트랩 화면 |
| 향끼리 방향 거리 | **0.1 이상** | `analyze_run.py` |
| 보드 온도 | 42~43도 안정 | 화면 |
| 파싱 채택률 | 90% 이상 | 파싱 출력 |

### 5-2. 증상별 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| S값 0.05 미만 | 향이 센서에 안 닿음 | 에어컨 바람 차단, 뚜껑 확인, 오일 보충 |
| 전부 Air로 나옴 | 기준선이 오염된 상태로 잡힘 | 환기 후 `--reset` |
| 한 향으로 몰림 | 농도 과다 (포화) | `cycle_unit` 모델, 오일 줄이기 |
| 두 향이 안 갈림 | 향이 화학적으로 유사 / 병 노화 | 오일 새로 채우기, 향 종류 교체 |
| 판정이 계속 바뀜 | 기준선 불안정 | 예열 더, `--alpha` 낮추기 |

### 5-3. 로그 남겨서 분석

```powershell
python predict_serial.py --port COM5 --model scent_model_unit.pkl --log run.csv --mark Citrus
```
향 바꿔가며 `--mark Floral`, `--mark Woody`로 같은 파일에 이어 붙인 뒤:

```powershell
python analyze_run.py run.csv --train featuresN_bc.csv
```

**"방향 거리" 한 줄이 답을 준다:**

- 자기 클래스가 1등 → 조건은 맞음, 소프트웨어로 해결 가능
- 엉뚱한 클래스가 1등 → 향의 지문 자체가 학습 때와 다름 → 재수집

## 6. 실패해도 괜찮은 이유

세 향 구분이 끝내 안 되더라도 **캡스톤 데모는 성립한다.**

핵심 동작은 "향이 없으면 분사, 감지되면 정지"이고, 이건 **Air vs 향 있음**
판별이다. 이건 신호 크기만 보면 되므로 날짜가 바뀌어도 안정적이다.

| 구성 | 성능 |
|---|---|
| Air vs 향 있음 | ~99% |
| 4클래스 전체 | 90% 내외 |

최악의 경우 "폐루프 완성 + 다중 향 분류는 진행 중"으로 프레이밍해도
충분히 좋은 결과다.

## 7. 운영 권장 — 데모 당일 아침에 재수집

MOX 가스센서의 날짜 단위 드리프트는 이 분야의 알려진 난제다.
기준선 차감이 레벨은 잡아주지만 지문 모양의 변화까지는 못 잡는다.

파이프라인이 완성돼 있으므로 **수집 40분 + 학습 5분**이면 그날 조건에
맞춘 모델이 나온다. 발표 전날이나 당일 아침에 한 번 돌리는 것을
루틴으로 잡는 것이 가장 확실하다.
