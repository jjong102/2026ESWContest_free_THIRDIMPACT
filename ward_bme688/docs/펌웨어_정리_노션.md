# 와드(WARD) — BME688 향 분류 펌웨어 정리

> 캡스톤 "와드" 프로젝트에서 직접 만든 **학습(데이터 수집)** 과 **추론** 펌웨어 기록.
> 모든 펌웨어는 Bosch BME688 DevKit(8센서, ESP32)용 Arduino 스케치.
> 베이스: Bosch `bme688_dev_kit.ino` (BSD-3-Clause) → 프로젝트 목적에 맞게 개조.

## 1. 절대 불변식 — 히터 프로파일 일치 ★

**수집 때와 추론 때의 히터 프로파일(온도 프로그램)이 한 글자도 달라선 안 된다.**
프로파일이 다르면 가스 센서의 "지문 모양"이 달라져 학습된 모델이 통째로 무효가 된다.

- 공통 측정 주기: `MEAS_DUR = 140 ms`
- 단일 프로파일(HP354):
  - `tempProf = {320, 100, 100, 100, 200, 200, 200, 320, 320, 320}`
  - `mulProf  = {5, 2, 10, 30, 5, 5, 5, 5, 5, 5}`

`bme688_serial_stream.ino`와 `bme688_dev_kit_logger.ino`는 이 값을 **동일하게** 갖고 있어야 하며, 파서 스크립트의 표와도 일치해야 한다.

## 2. 학습(수집) 펌웨어

### 2-1. 공통 기능 (Bosch 원본에서 개조한 점)

| # | 기능 | 내용 |
|---|---|---|
| [1] | 파일명 자동 증가 | `LOG_0001.csv, LOG_0002.csv...` 빈 번호를 찾아 생성. 기존 파일 보존 (원본은 켤 때마다 삭제) |
| [2] | 무한루프 제거 | 인덱스 누락 시 정지(panic) 대신 놓친 개수만 세고 계속 진행 |
| [3] | 진행 상황 표시 | 10초마다 `[경과 / 사이클수 / 놓침 / 보드온도]` 시리얼 요약 |
| [4] | 시리얼로 세션 전환 | `'n'`으로 파일만 바꿈 → 예열은 처음 한 번만 (전원 유지로 열적 상태 일정) |
| [5] | 지연 기록 버퍼 | 데이터를 10초간 RAM 보류 후 기록. `p`/`n` 시 최근 10초(오염 구간) 자동 폐기 |
| [6] | 전환 직후 오카운트 방지 | 전환/재개 후 `RESYNC_MS=3s` 동안 인덱스 추종만, 놓침 판정 유예 |
| [7] | 보드 버튼 + LED 조작 | 노트북 없이 현장 조작. `SW_START(GPIO32)`, `SW_NEXT(GPIO14)` |
| [8] | 수동/자동 블록 모드 | 수동=시간제한 없음(안정화 측정), 자동=`AUTO_BLOCK_MS` 뒤 자동 저장 |
| [9] | 시리얼 라벨 입력 | 향 이름 입력 시 파일명에 자동 부착 (`woody` → `LOG_0031_Woody.csv`) |

### 2-2. 조작 요약 (두 로거 공통)

```
SW_START | 'p'        : 시작 / 일시정지
SW_NEXT(짧게) | 'n'   : 블록 종료 → 저장 + 정지
SW_NEXT(2초) | 'a'    : 수동 ↔ 자동 모드 전환
             's'      : 현재 상태 출력 (시리얼 전용)
향 이름 입력          : 이번 블록의 라벨 (air / citrus / floral / woody)
```

LED 신호: 느린 점멸=정지 / 빠른 점멸=시작 카운트다운 / 짧게 반짝=녹화중 / 길게 3번=블록 완료 / 짧게 2번=수동전환 / 짧게 4번=자동전환

### 2-3. `bme688_dev_kit_logger.ino` — 단일 프로파일 (10차원)

- 8센서 모두 같은 히터 프로파일(HP354).
- 파서: `parse_devkit_csv.py`
- 결과 특징: 10차원 (log_gas_0~9)

### 2-4. `bme688_multiprofile_logger.ino` — 프로파일 4종 (40차원, 최신)

- **문제의식**: 8센서를 같은 온도로 돌리면 같은 측정을 8번 반복 → 정보가 10차원에 머묾 (특징공학해도 0.526→0.516로 개선 없음).
- **해법**: Bosch 원본 탐색 모드처럼 **4가지 프로파일을 2센서씩** 배정. 서로 다른 온도 프로그램이 서로 다른 화학 정보를 끌어냄 → 파서에서 합쳐 **40차원**.

| 센서 | 프로파일 | 성격 | 사이클 길이 |
|---|---|---|---|
| 0,1 | HP354 | 표준 (320 초기화 후 100℃ 유지 2/10/30) | 11.5초 |
| 2,3 | HP501 | 완만 (210-265-320-...-100) | 26.9초 |
| 4,5 | HP411 | 급전이 (100↔320 왕복 후 240 유지) | 24.6초 |
| 6,7 | HP301 | 장시간 (100/200/320 각각 길게 유지) | 18.3초 |

```c
PROF_TEMP[4][10] = {
  {320, 100, 100, 100, 200, 200, 200, 320, 320, 320},  // HP354 표준
  {210, 265, 265, 320, 320, 265, 210, 155, 100, 155},  // HP501 완만
  {100, 320, 170, 320, 240, 240, 240, 320, 320, 320},  // HP411 급전이
  {100, 100, 200, 200, 200, 200, 320, 320, 320, 320},  // HP301 장시간
};
PROF_MUL[4][10] = {
  { 5,  2, 10, 30,  5,  5,  5,  5,  5,  5},
  {24,  2, 22,  2, 22, 24, 24, 24, 24, 24},
  {43,  2, 43,  2,  2, 20, 21,  2, 20, 21},
  { 2, 41,  2, 14, 14, 14,  2, 14, 14, 14},
};
```

- 파서: `parse_devkit_multi.py` (센서 {0,2,4,6}=배열 A, {1,3,5,7}=배열 B)
- **주의**: 단일 프로파일 데이터와 호환 안 됨 → 전면 재수집 필요. 느린 프로파일이 ~27초라 블록은 5분 이상 권장(`AUTO_BLOCK_MS=420000`).

### 2-5. 수집 CSV → 학습 흐름

```powershell
python parse_devkit_multi.py data7\Air ... --label Air   # (프로파일별 파서)
# 클래스별 CSV concat → features7.csv
python baseline_correct.py features7.csv features7_bc.csv # 인접 Air 기준선 차감
python train_scent.py features7_bc.csv --no-temp-hum      # RF 학습 + confusion matrix
```

## 3. 추론 펌웨어

### 3-1. `bme688_serial_stream.ino` — PC 파이프라인용 (권장)

- WiFi / MQTT / SD 없이 **USB 케이블 하나**로 원측정값을 스트리밍.
- PC의 `predict_serial.py`가 받아서 sklearn 모델로 실시간 판정.
- 히터 프로파일 = 로거와 동일(HP354). `MEAS_DUR=140`, `BAUD=115200`.

**출력 형식** (더미 슬롯 Gas Valid=0은 전송 안 함, 안내문은 `#`로 시작):
```
D,센서,스텝,가스저항,온도,습도
예) D,3,7,182345.6,42.85,23.10
```

**사용법**:
1. 업로드 후 아두이노 시리얼 모니터를 **반드시 닫는다** (포트 충돌 방지)
2. `python predict_serial.py --port COM5`
3. 발향 끈 상태로 1~2분 → 기준선 자동 확립
4. 향 투입 → 화면에 판정 실시간 갱신

### 3-2. `bme688_bsec_infer.ino` — 온디바이스 BSEC 추론

- BME AI-Studio로 학습한 **4클래스 selectivity 알고리즘**을 BSEC로 보드에서 직접 실행.
- 8센서 각자 확률을 내고 **평균**해서 최종 판정.

**클래스 매핑 (aiconfig 순서, 절대 변경 금지)**:
```
GAS_ESTIMATE_1 = Air
GAS_ESTIMATE_2 = Citrus
GAS_ESTIMATE_3 = Floral
GAS_ESTIMATE_4 = Woody
```

**출력 예**:
```
[S6] Air 0.02  Citrus 0.91  Floral 0.05  Woody 0.02
>>> CITRUS   (8센서 평균, 최대 0.88)
```

**셋업 주의점**:
- `commMux.h/.cpp`를 폴더에 복사 (카멜케이스 판 사용: `commMuxBegin` 등).
- AI-Studio 내보내기 파일 이름 맞추기: `aircitrusfloralw_354_10.c/.h` → `bsec_serialized_configurations_selectivity.c/.h`
- **BSEC 버전 2.6.1.0** 필수 (다르면 `setConfig`가 `-34` 반환).
- selectivity(IAQ_Sel) 알고리즘 바이너리를 쓰는 bsec2 라이브러리여야 함 (IAQ 전용이면 4클래스 동작 안 함).
- 구독은 `GAS_ESTIMATE 4개만` — RAW_GAS 등을 섞으면 구독 전체가 `-12`로 거부됨.
- 자주 만나는 에러: `-34`(버전 불일치) / `-12`(스캔 모드 미지원 출력 구독) / `-14`(샘플레이트 불일치).

### 3-3. 두 추론 방식 비교

| | serial_stream + PC | bsec_infer (온디바이스) |
|---|---|---|
| 판정 위치 | PC (Python sklearn) | 보드 (BSEC) |
| 모델 교체 | 쉬움 (pkl만 교체, 당일 재학습) | 어려움 (AI-Studio 재학습→플래시) |
| 의존성 | USB + PC 필요 | 보드 독립 실행 |
| 기준선 차감 | O (predict_serial.py) | BSEC 내부 처리 |
| 용도 | 실험·튜닝·데모 주력 | 순정 파이프라인 대조군 |

## 5. 기억해 둘 것 (교훈)

- 히터 프로파일은 **수집=추론** 완전 일치가 대전제. 바꾸면 모델 전부 무효.
- 향끼리 연달아 찍지 말고 **Air와 교대**로 수집 (기준선 차감용). 어겼을 때 정확도 24%까지 하락한 적 있음.
- MOX 센서는 날짜 단위 드리프트가 심함 → **데모 당일 아침 재수집+재학습**이 가장 확실.
- 라벨은 SD 꽂자마자 파일명에 부착 (Woody/Citrus 뒤바뀐 사고 이력).
